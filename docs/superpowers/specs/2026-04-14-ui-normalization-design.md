# Hub UI 정규화 설계

## 목적

Hub UI를 실제 운영 데이터에 맞게 정규화. 최종 목표: 주문만 관리하고, 상품가공→등록 순환이 자동으로 돌아가는 구조.

당장 급한 것: **고도몰 9,900개씩 카테고리별 상품 등록**.

---

## 현재 문제

### 1. 상품 가공상태 불일치
- `text_status`, `image_status` 컬럼 = **전부 NULL** (한 번도 세팅 안 됨)
- 실제 가공 여부는 각 단계 컬럼 존재 여부로 판단해야 함:
  - **텍스트 완료** = `ST4_마켓상품명 IS NOT NULL` (47,139 / 54,000 = 87%)
    - 가공 체인: ST1→ST2→ST3→ST4 (ST4까지 있어야 완료)
  - **이미지 3단계**:
    - `없음` = 누끼url NULL (5,598건)
    - `누끼만` = 누끼url 있고 연출url NULL (4,996건)
    - `완료` = 누끼url + 연출url 모두 있음 (43,406건 = 80%)
    - 추후: ST2_JSON 기반 생성형 이미지 파이프라인 추가 예정 (미진행)
  - ST2 완료 = `ST2_JSON IS NOT NULL` (43,218 / 54,000 = 80%)

### 2. 스토어 관리 + 등록 파이프라인 분리 불필요
- `#stores`와 `#pipeline-register`가 별도 페이지
- 사용자: "통합하면 될 거 같은데 굳이 나눌 이유가?"
- 마켓별 세로 트리뷰 필요 (현재: 단순 테이블)

### 3. 공급사 페이지 버튼 과다
- 4개 OC 버튼 (전체 신규수집, DB 추출, OC 동기화, 전체 스캔) → 혼란
- 핵심 정보: OC 상품수 → DB 상품 → 미가공 관계

### 4. 대시보드 배송비 탭 미구현
- `oc_shipping_fee`, `oc_shipping_type` 데이터는 있음

---

## 결정 사항

| 항목 | 결정 |
|------|------|
| text_status/image_status | DB 컬럼 기반 자동 계산 (쿼리 시 CASE WHEN) |
| 스토어 + 등록 파이프라인 | 통합 → `#stores` 하나로 (마켓별 트리뷰 + 카테고리 배정 + Excel 출고) |
| `#pipeline-register` 페이지 | 삭제 (스토어 관리에 통합) |
| 공급사 버튼 | 2개로 축소 (주간 스캔 + DB 추출) |
| 대시보드 | 가공 현황 카드 + 배송비 통계 추가 |

## 페이지별 설계

### 1. 대시보드 (`#dashboard`)

**현재**: 4개 통계 카드 + OC 동기화 버튼 + 마켓 현황
**변경**:

```
┌─────────────────────────────────────────────────┐
│ 📊 가공 현황                                      │
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐    │
│ │54,000│ │52,687│ │43,406│ │43,218│ │47,139│    │
│ │전체  │ │텍스트│ │이미지│ │ST2   │ │출고가│    │
│ │ACTIVE│ │완료  │ │완료  │ │완료  │ │능    │    │
│ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘    │
├─────────────────────────────────────────────────┤
│ 📦 배송비 현황                                     │
│ 무료배송: N개 | 조건부무료: N개 | 유료: N개         │
├─────────────────────────────────────────────────┤
│ 🏪 마켓별 등록 현황 (기존)                          │
└─────────────────────────────────────────────────┘
```

가공 현황 카드 계산 SQL:
```sql
-- 텍스트 완료 (ST4까지 완료)
COUNT(CASE WHEN ST4_마켓상품명 IS NOT NULL AND ST4_마켓상품명 != '' THEN 1 END)
-- 이미지 완료 (누끼+연출 모두)
COUNT(CASE WHEN 누끼url IS NOT NULL AND 누끼url != '' AND 연출url IS NOT NULL AND 연출url != '' THEN 1 END)
-- 이미지 부분 (누끼만)
COUNT(CASE WHEN 누끼url IS NOT NULL AND 누끼url != '' AND (연출url IS NULL OR 연출url = '') THEN 1 END)
-- 출고 가능 (ST4 + 누끼url + 가격)
COUNT(CASE WHEN ST4_마켓상품명 IS NOT NULL AND ST4_마켓상품명 != ''
           AND 누끼url IS NOT NULL AND 누끼url != ''
           AND oc_price IS NOT NULL AND oc_price > 0 THEN 1 END)
```

### 2. 상품 DB (`#products`)

**변경**:
- `text_status` / `image_status` 컬럼 → CASE WHEN 계산으로 대체
  - 텍스트: `ST4_마켓상품명` 존재 → 'done', 없으면 'todo'
  - 이미지: `누끼url` + `연출url` 모두 → 'done', 누끼만 → 'partial', 없으면 'todo'
- quick_filter 추가: `shippable` (출고 가능 = ST4 + 누끼url + 가격 모두 있음)
- 배송비 컬럼 추가: `oc_shipping_fee` / `oc_shipping_type`

핵심 변경:
- 마켓별 세로 컬럼 레이아웃 (트리뷰)
- 스토어 클릭 → 하단에 카테고리 배정 + 가격 전략 + Excel 생성 통합
- `#pipeline-register` 삭제, 기능을 여기로 흡수

### 4. 공급사 관리 (`#vendors`)

**기능 축소**:
- 공급사 목록 테이블 (핵심 정보만)
- 공급사 추가 (수동 등록 / OC에서 sync)
- 공급사별 카테고리 분포 표시

**테이블 설계**:
```
공급사코드 | 공급사명 | 전체DB → 활성화 → 가공완료 | 주요 카테고리 | 상태
V001      | 테스트   | 24,917 → 1,482 → 1,200  | 생활>문구    | 활성
```
- **전체DB** = oc_catalog.db에서 해당 vendor의 전체 상품 수
- **활성화** = oc_catalog.db에서 status='available' (정상 판매 가능)
- **가공완료** = products.db에서 해당 vendor의 ST4_마켓상품명 있는 수
- **주요 카테고리** = products.db 카테고리명 기준 최다 카테고리 (OC 카테고리)
- 화살표(→)로 퍼널 관계 시각화

**버튼**:
```
+ 공급사 추가    ← 수동 등록 폼
🔄 동기화       ← vendor-scan (등록 공급사 최신화)
```

### 5. 삭제 페이지

- `#pipeline-register` → 스토어 관리에 통합
- `#pipeline` → 미구현 placeholder, 나중에 가공 파이프라인 연동

## API 변경

### 수정

| 엔드포인트 | 변경 |
|-----------|------|
| `GET /api/dashboard` | 가공 현황 5개 카드 + 배송비 통계 추가 |
| `GET /api/products` | text_status/image_status CASE WHEN 계산, 배송비 컬럼 추가 |

### 신규 없음 (기존 API 활용)

등록 파이프라인 API (`/api/register/*`)는 그대로 유지 — JS에서 호출하는 페이지만 변경.

---

## 구현 순서

1. **dashboard 가공 현황 카드** — SQL 변경 + JS 렌더
2. **products 가공상태 계산** — CASE WHEN + 배송비 컬럼
3. **stores 통합 리디자인** — 마켓별 트리뷰 + 등록 파이프라인 흡수
4. **vendors 버튼 정리** — 2개로 축소 + 카운트 관계 표시
5. **pipeline-register 삭제** — nav/app.js에서 제거
