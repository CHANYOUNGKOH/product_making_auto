# 클린대상 — 운영자 1회 설명

> 이 템플릿은 사용자가 **한 파트당 한 번만 채운다**. 이후 Codex가 이 문서 + 코드 감사 결과로 기술 선택·구현.

## 1. 목적 (왜)
클린대상 파트는 네이버쇼핑 클린대상으로 분류된 상품을 추적하고 클린 사유별로 분류하기 위해 필요하다.

예: "고도몰 A1-1 스토어의 슬롯이 9,900인데, 현재 8,200 밖에 안 차 있어서 매출 손실."

## 2. 자료 출처 (어디서 얻나)
- 데이터 출처 이름 + 경로 (URL, API, DB 테이블, 엑셀 파일 등)
- 인증 정보 필요하면 "어디에 있음" (실제 값은 적지 말 것)

예:
- 쇼핑파트너센터 상품리포트 → https://...
- OrderHelper DB `orders` 테이블
- 엑셀: `C:\...\슬롯관리.xlsx`

## 3. 해야 할 일 (무엇을)
순서대로 나열. 애매한 표현 피하기.

예:
1. SP 리포트에서 최근 30일 주문 0건 상품 목록 추출
2. 해당 상품을 고도몰 삭제 API 로 삭제
3. 같은 스토어의 common-ready 풀에서 신규 1건 뽑아 등록

## 4. 입력 / 출력
- 들어오는 것: 어떤 파일·데이터·이벤트?
- 나가는 것: 어떤 파일·DB row·알림?

## 5. 제약·주의 (지키지 못하면 안 되는 것)
- 금지 사항
- 회복 불가능한 작업(삭제·PR merge·메시지 전송 등)은 운영자 확인 필수
- 기존 관련 memory 파일 (있으면 경로)

## 6. 기술 선택은 공란 (Codex 가 채움)
- 프레임워크: ___
- 라이브러리: ___
- 플러그인: ___
- 테스트 방식: ___

## 7. 운영자만 아는 정보 (있으면)
- 마켓 계정 ID, 스토어 별칭, 담당자 이름 등
- 과거에 실패한 방식 (중복 시도 방지)
